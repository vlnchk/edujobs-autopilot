# Implementation Decisions

This log records implementation decisions that are necessary but not already defined by `WORKFLOW_A_IMPLEMENTATION_SPEC.md` version 2.3.1. The canonical spec always takes precedence.

Do not use this file to restate requirements or invent business rules. For each future decision, record the date, status, context, decision, and consequences.

## Current decisions

### D-001 — Worker safety defaults and DNS policy

- **Date:** 2026-09-04
- **Status:** Accepted
- **Context:** The spec requires configurable limits and rejection of internal destinations but does not assign local defaults or define behavior for DNS names with mixed public/private answers.
- **Decision:** Default to a 15-second fetch timeout, 3 redirects, 10,000,000 downloaded bytes, and 200,000 extracted characters. Accept a destination only when every resolved address is globally routable; reject URL-embedded credentials and scoped IP literals. Ignore ambient HTTP proxy settings so the validated destination is the one contacted.
- **Consequences:** Deployments can override every limit through the spec-defined environment variables. Resolution is deliberately conservative and prevents mixed DNS answers from providing an internal-network path.

### D-002 — MVP source detection and Browserless boundary

- **Date:** 2026-09-04
- **Status:** Accepted
- **Context:** The spec defines supported source families and one Browserless fallback but does not prescribe source-detection precedence, the Google Docs retrieval form, or the Browserless endpoint path.
- **Decision:** Detect known Google Docs, Notion, and unsupported social hosts from the submitted URL, then use response content type and PDF/DOCX signatures for ordinary sources. Retrieve standard public Google Docs through their DOCX export; treat published Google Docs and Notion as HTML. For unusable HTML, call the configured `BROWSERLESS_URL` once, defaulting to `http://browserless:3000/content`. Treat only confirmed HTTP 404/410 as `LINK_BROKEN`; keep other retrieval or parsing failures technical.
- **Consequences:** Detection remains deterministic and format-specific without crawling. Browserless receives only a target already accepted by the worker's public-destination validation. Malformed supported documents fail extraction, and oversized output fails rather than being truncated.

### D-003 — Deterministic workflow-logic representation and normalization

- **Date:** 2026-09-04
- **Status:** Accepted
- **Context:** M3 business checks must remain outside the Python content worker and later fit n8n, while the spec intentionally leaves exact syntactic normalization details open.
- **Decision:** Implement M3 as one dependency-free ES module tested with Node's built-in test runner. URL normalization accepts only credential-free HTTP(S), uses standard URL canonicalization, removes fragments, and preserves paths and queries. Duplicate-description comparison collapses whitespace but preserves case and punctuation. Contact parsing accepts syntactically valid email, 7–15 digit phone numbers, Telegram usernames, and direct `t.me` paths; usernames ending in `bot` are bots. Apply deterministic short-circuit precedence as invalid Project Link, then contact failure, then exact duplicate.
- **Consequences:** Matching remains conservative: no tracking-parameter removal, fuzzy text comparison, DNS lookup, Telegram lookup, or semantic classification occurs. A plain `t.me/username` is treated as a direct contact unless it uses a known non-user path; channel-versus-user identity cannot be resolved syntactically and remains outside M3.

### D-004 — Manual row selection and first-run UUID generation in n8n

- **Date:** 2026-09-04
- **Status:** Accepted
- **Context:** The spec permits the current Google Sheets row identifier during first processing, requires exact duplicate checks against existing applications, and requires a UUID without prescribing how the n8n Code sandbox obtains one. The default n8n Code sandbox does not expose Node's `crypto` module or the Web Crypto global.
- **Decision:** Require `WORKFLOW_A_TEST_ROW_NUMBER` for the inactive M4 manual entrypoint, read the configured sheet once, select exactly that one `row_number`, and use only strictly earlier rows as duplicate candidates. Generate a candidate version-4 UUID with n8n's built-in Crypto node, while always preserving an existing `application_id` on re-run.
- **Consequences:** The workflow never searches for or batch-processes `NEW` rows. The sheet-wide read is used only for explicit selection and conservative M3 duplicate comparison; only one selected application enters the pipeline. UUID generation needs no Code-node module allowlist or external service.

### D-005 — Local sandbox image and network boundary

- **Date:** 2026-09-05
- **Status:** Accepted
- **Context:** The spec pins n8n 2.35.7 and requires a minimal three-service sandbox with an internally reachable worker, but it does not select the Python patch image, Browserless patch image, host binding, or health-probe mechanism.
- **Decision:** Build the worker from `python:3.12.13-slim-bookworm`, pin Browserless to `ghcr.io/browserless/chromium:v2.55.3`, and publish only n8n on `127.0.0.1:5678`. Keep Browserless and the non-root, read-only worker un-published on one Compose bridge network, and use dependency-free liveness endpoints for startup verification. The automated disposable check may request an ephemeral n8n host port to avoid colliding with an unrelated local service.
- **Consequences:** The sandbox remains able to reach OpenAI, Google, and supplied public URLs while neither supporting service has a host-facing port. Image/runtime behavior is repeatable, local startup can be health-gated, and the verification harness does not disturb an existing process on port 5678.

### D-006 — Post-M7 test range execution and row-isolation evidence

- **Date:** 2026-09-05
- **Status:** Accepted
- **Context:** The post-M7 test runner must supply one row per Workflow A execution, wait sequentially, retain manual `WORKFLOW_A_TEST_ROW_NUMBER` behavior, obtain execution results, and determine which application rows changed without adding a production batch path or a new service. The repository uses local n8n SQLite and an inactive Manual Trigger workflow.
- **Decision:** Use n8n's synchronous CLI `execute` command for one separate process per requested row. Supply a runner-only `WORKFLOW_A_RUNNER_ROW_NUMBER` process environment value that takes precedence over, but does not replace, the manual selector. The runner temporarily stops the local n8n service for exclusive SQLite access while Browserless and the worker remain available. Only in runner mode, read the Sheet after canonical persistence and compare complete pre/post row snapshots; require the changed-row set to equal the selected row exactly.
- **Consequences:** Workflow A still handles exactly one application per execution and retains one `row_number`-matched update. Manual/production-oriented paths do not perform the extra verification read. Ordinary failures before persistence record no write and do not stop later cases; an unexpected row change or unverifiable state after persistence stops the range to protect test data. Concurrent human edits to the same Sheet during a run are intentionally reported as isolation violations.

### D-007 — Conservative shared recruiting URL syntax

- **Date:** 2026-09-06
- **Status:** Syntax heuristic retained; ambiguous-URL behavior superseded by D-010
- **Context:** The canonical spec now requires identical Original Links to short-circuit only for vacancy-specific URLs and requires conservative deterministic recognition of shared recruiting pages, but it intentionally does not prescribe the exact syntactic classifier.
- **Decision:** Classify a normalized HTTP(S) URL as shared/generic only when it has no query string and its final non-empty path segment, compared case-insensitively, exactly matches this closed allow-list: `career`, `careers`, `jobs`, `vacancies`, `job-openings`, `open-positions`, `current-openings`, `career-opportunities`, `employment-opportunities`, `work-with-us`, `join-us`, or `join-our-team`. Do not infer from the hostname, use substring/fuzzy matching, inspect content, crawl, or add domain exceptions.
- **Consequences:** The discovered `/career` case is handled, as are a small set of high-confidence equivalent landing/index paths and nested locale/company paths ending with those labels. Root URLs, query-bearing pages, unfamiliar labels such as `/opportunities`, and descendant vacancy paths such as `/jobs/123` remain vacancy-specific; this intentionally favors false negatives over false-positive rejection when classification is ambiguous.

### D-008 — High-confidence deterministic editorial content-loss guard

- **Date:** 2026-09-08
- **Status:** Accepted
- **Context:** The canonical validator already defines `MEANING_LOST`, but it does not prescribe how deterministic validation should identify a title-only, heading-only, trivial, or severely collapsed draft without turning concise rewriting into a textual-similarity requirement.
- **Decision:** Run one shared high-confidence content-preservation check for generated MINIMAL/ENRICH drafts and deterministic KEEP output before publication. Ignore URL/contact-only and recognized navigation, call-to-action, recommendation, policy, and footer blocks. Reject intrinsically trivial headings/titles and exact short source blocks. For a substantial reference (at least 24 meaningful tokens plus at least three substantive units or two recognized vacancy-information facets), reject only when combined structural, facet-preservation, lexical-anchor, and extreme token-reduction signals show clear collapse. Include successfully acquired required Original Link content and extracted source titles as rejection-only completeness references; do not expose them as factual input to the MINIMAL editor. Use the existing `MEANING_LOST` issue and existing fallback chain. Leave ambiguous semantic preservation to the LLM validator, whose prompt explicitly permits concise rewriting and boilerplate removal.
- **Consequences:** An LLM `PASS` can no longer publish a title or similarly obvious fragment, including during ENRICH → MINIMAL fallback. Concise posts that retain responsibilities, requirements, and important work conditions are not required to preserve every sentence or a fixed percentage of source characters. When all modes reduce to an intrinsically insufficient Short Description, the existing KEEP failure path ends in `NEEDS_REVIEW`.


### D-009 — Shared editor for optional reviewer drafts

- **Date:** 2026-09-08
- **Status:** Accepted
- **Context:** The draft feature requires downstream editorial work independent of eligibility but does not prescribe the node reuse, conservative sufficiency gate, or handling of optional editor failures.
- **Decision:** Route pre-editor review/rejection outcomes through a deterministic gate into the existing external-context-capable editor/validator nodes. Keep public editorial modes null; a transient draft-only marker selects presentation handling. Reuse existing meaningful-body helpers to skip empty/noise/title-only input; require submitted vacancy content or already approved Original Link content, never an employer page alone. Exclude explicitly disputed source contexts only from the transient draft input. Leave optional failed output empty without revising the established outcome, and do not restart exhausted accepted fallback chains. Rename the editor candidate response field to draft_description so final_description is reserved for publication finalization.
- **Consequences:** No second editor pipeline, new LLM endpoint, source fetch, eligibility pass, status, or database is introduced. Normal accepted generation cost is unchanged. Existing publication telemetry is preserved; optional draft checks and fact evidence remain in execution data. Reprocessing intentionally replaces generated columns under canonical Section 6.4.


### D-010 — Submitted vacancy evidence for reused Original Links

- **Date:** 2026-09-09
- **Status:** Accepted
- **Context:** The user reported distinct teaching vacancies sharing an unrecognized recruiting-page URL. Intake has no separate role/title field, and path recognition alone cannot prove that a URL identifies a single vacancy.
- **Decision:** Retain D-007's path heuristic and exact Project Link plus Short Description fallback. For an Original Link match on other paths, additionally require equal normalized Project Links and non-empty complete Short Descriptions equal after whitespace normalization and lowercasing. Different submitted text makes the URL potentially shared for that comparison. Use full submitted text as conservative role/vacancy evidence instead of extracting titles, applying semantic/fuzzy similarity, or adding path/domain exceptions.
- **Consequences:** Different roles sharing any URL cannot trigger Original Link rejection; case/whitespace-equivalent submissions with matching projects still can. Same titles with different substantive details also remain distinct. Explicit shared paths keep their existing exact secondary rule. Earlier-row and same-application exclusions, persisted match labels, and every downstream operation remain unchanged.

### D-012 — Shared editorial URL comparison without intake normalization changes

- **Date:** 2026-09-09
- **Status:** Accepted
- **Context:** The URL-boundary fix requires shared canonical comparison in a secure n8n VM without a `URL` global. Existing whole-field intake normalization removes fragments for duplicate detection, which must not redefine editorial source grounding.
- **Decision:** Keep one self-contained editorial extraction/canonicalization function in `workflow-logic/url-text.mjs` and embed its exact function text through the builder. Stop on unmatched closing brackets and formatting delimiters; preserve balanced URL brackets and interior punctuation. Treat literal terminal sentence punctuation as prose, preserving percent-encoded punctuation. Normalize scheme/host case, standard default ports, empty paths, Unicode suffix encoding and conservative percent escapes; preserve query order/values, fragments, path case and reserved escapes. Do not infer a boundary inside an uninterrupted valid Unicode path merely because it contains Cyrillic letters.
- **Consequences:** Sources and drafts share exactly one comparison path without changing source approval or fallback. Whole-field intake/duplicate parsing, contact recognition, lexical URL removal and worker network validation keep their separate contracts. Ambiguous raw terminal punctuation should be percent-encoded when it belongs to the address; this helper does not attempt full browser URL resolution or fetch validation.

### D-014 — Bounded inline Markdown placement and candidate-scoped metadata

- **Date:** 2026-09-20
- **Status:** Accepted
- **Context:** The hyperlink amendment specifies visible-text insertion, candidate isolation and useful reviewer preservation, but does not prescribe a Markdown parser, transient metadata storage or the representation of semantic selection-only failures.
- **Decision:** Embed one self-contained `insertProjectLink` helper in the existing n8n Code nodes. Parse a bounded inline Markdown subset with source spans used only transiently: escaped text, literal balanced brackets, emphasis/strong/strikethrough, inline links, whole inline-code mentions and common HTML entities. Preserve surrounding list/heading syntax, exclude URLs/autolinks from selection, and leave unsupported images/reference links/HTML/titled links, overlapping labels, partial code spans and ambiguous/unbalanced syntax unresolved. Percent-encode generated destination delimiters and Unicode while preserving existing URL escapes; preserve equivalent correct existing links. Verify idempotence before accepting a generated wrapper. Keep EligibilityDecision's submission selection transiently for KEEP fallback; Sheet `project_link_text` is populated only from the actual retained candidate. Reconstructed reviewer bodies reset failed-candidate metadata; under Section 6.7, recovery may reuse the submission selection when the complete sanitized submission remains the exact opening segment and shared-helper placement preserves appended context (clarified 2026-09-21). Meaning-preservation heuristics inspect pre-wrapper wording, while final links, URL grounding and diagnostic lengths inspect the stored representation.
- **Consequences:** No new node, model call, source request, dependency or Sheet destination/offset column. Pre-insertion model URL checks remain authoritative; only the deterministic wrapper receives the submitted destination. The existing validator identifies a selection-only semantic failure using `OTHER_CONTRACT_VIOLATION` with issue text exactly `project_link_text` and still checks all factual issues. Only a reviewer result whose issues are exclusively that marker retains the pre-wrapper factual candidate with null selection; any factual failure keeps existing rejection/recovery behavior. This permits useful reviewer text without treating link success as eligibility or destination verification. Parser limitations are deliberate conservative review cases, not business rejection rules.

### D-015 — Preserve the origin of a validated contradiction across fallback

- **Date:** 2026-09-24
- **Status:** Superseded by D-024 (2026-10-06 amendment: identity mismatches are decided only by EligibilityDecision; ValidationResult has no `source_conflict`)
- **Context:** Sections 13.9/20 require unresolved material source conflicts to remain non-publishable; Section 15 permits fallback to recover errors introduced by an editor. The existing CONTRADICTION issue does not structurally distinguish these origins. The spec does not prescribe transport/storage of this distinction.
- **Decision:** Extend each issue in the existing strict ValidationResult response with required boolean `source_conflict`, true only for CONTRADICTION already present in permitted original inputs independently of the candidate. Preserve true findings in transient `m6.source_conflicts` during accepted processing and enforce them through the existing publication checks/fallback. Retain detailed reasons for terminal review and the existing issue-only history shape. Candidate-only contradictions remain recoverable. The distinction remains semantic and is not inferred from free-form reasons, numeric overlap, titles or clarification phrases. Optional reviewer checks cannot revise their authoritative outcome. This choice defines no precedence between broad experience categories and detailed requirements, no title-equivalence policy and no historical golden classification; the canonical specification is unchanged.

### D-016 — Preserve an established material gap across fallback

- **Date:** 2026-09-25
- **Status:** Accepted implementation choice; record format superseded by D-024 (gaps name EMPLOYER, ROLE or WORK without quotations). The fallback-blocking rule remains.
- **Context:** Sections 13.1 and 13.10 make the combined EligibilityDecision compare the submission with approved context and select ENRICH for material vacancy-information gaps; Section 13.1 states that MINIMAL cannot supply those external facts; Sections 6.3, 13.5 and 14.3 forbid publishing a result that loses material vacancy meaning. Section 13.3.1 limits the MINIMAL editor to the Short Description, Section 14.1 gives the MINIMAL validator only context actually used (none), and Section 14.4 permits required Original Link content only as a rejection-only completeness reference for deterministic validation. The spec does not prescribe how the eligibility comparison survives an ENRICH → MINIMAL → KEEP mode change. Saved execution 436 showed that it does not: the semantic finding was prose, the MINIMAL validator received `{}` and the lexical guard cannot see missing details inside retained categories.
- **Decision:** Extend the existing strict EligibilityDecision response with required `material_gaps`, an array of `{detail, source, evidence}` records. It is non-empty only for ACCEPT + ENRICH; `source` is limited to `original_link`; `evidence` must be a whitespace-normalized contiguous quote of approved Original Link `used_context` containing material, non-noise text. Violations use the existing one-retry contract path. Keep the records transient in `state.material_gaps`. The accepted ENRICH validator receives them as completeness obligations; the MINIMAL deterministic check and deterministic KEEP add `MEANING_LOST` whenever they are non-empty, and terminal persistence refuses READY_FOR_PUBLISH through MINIMAL/KEEP with recorded gaps. KEEP's review reason lists the missing details.
- **Consequences:** No model call, classifier, retry loop, node, Sheet column, source or length rule is added. MINIMAL editor and validator inputs are unchanged, so MINIMAL's factual sources are not broadened; the gaps are used for MINIMAL/KEEP only as a deterministic rejection reference derived from approved Original Link content, as Section 14.4 permits. Fallback still regenerates MINIMAL from the original submission and remains available when ENRICH was chosen only to improve a materially complete submission (empty gaps). A wrongly recorded gap produces conservative review, not publication. Project Link content creates no fallback obligation, preserving the D-008 boundary; a vacancy described only by Project Link therefore keeps the pre-existing semantic limitation. Suggested ratification: add `material_gaps` to Section 10.2 and state in Section 14.4 that these records are rejection-only references for MINIMAL/KEEP fallback.

### D-017 — Explicit provenance for the code-created Project Link at the validator boundary

- **Date:** 2026-09-25
- **Status:** Superseded by D-024 (the validator receives the editor's body without the code-created link, so no wrapper metadata or disregard filter exists)
- **Context:** Section 6.7 makes the deterministic wrapper authorized presentation metadata that is not an external fact, while pre-insertion checks prohibit model-invented URLs and existing validators check selection. In execution 436 the validator nevertheless returned FORBIDDEN_SOURCE_USAGE solely for that wrapper despite the prompt instruction; the request exposed the destination only inside the linked text. The spec does not prescribe the validator representation of this provenance or the handling of an issue that targets only authorized metadata.
- **Decision:** When the deterministic output check inserts or re-targets the wrapper, attach `code_created_project_link = {linked_text, destination, provenance}` to the transient draft and send it as `workflow_metadata` to the MINIMAL, ENRICH and reviewer validators and their contract retries; an editor-authored grounded link yields `null`. The prompt describes that metadata instead of repeating the old exception. After a contract-valid ValidationResult, disregard only an issue with `source_conflict=false` whose text cites no URL except that canonical destination and otherwise contains no words, or — for FORBIDDEN_SOURCE_USAGE, UNSUPPORTED_FACT and INVENTED_NUMBER_OR_DATE only — exactly the linked words when they occur verbatim in the normalized submission. Record disregarded issues in `m6.disregarded_link_issues`; decide PASS/FAIL from the remaining issues.
- **Consequences:** Model URLs are still rejected before insertion, the final linked text is still validated, and every other URL, claim, label or `project_link_text` selection issue remains authoritative, so an independent factual error still fails. The rule depends on the validator citing the offending text as its contract requires; an issue that mixes the wrapper with other text stays a failure. Validation history keeps its issue-only shape. No node, model call or Sheet column is added. The metadata and filter do not prove live model compliance.

### D-018 — Runner result recovery from the saved execution

- **Date:** 2026-09-25
- **Status:** Accepted implementation choice
- **Context:** D-006 obtains each row's verification from `n8n execute --rawOutput` stdout. n8n 2.35.7 `BaseCommand.finally()` calls `process.exit()` about 100 ms after printing the multi-megabyte result; executions 438 and 450 were saved successfully with a valid runner result, yet the runner received unparseable stdout, reported `Sheet write UNKNOWN` and stopped. A local `docker compose run` probe that exits immediately after printing delivered only the first 64 KiB. The spec does not prescribe how the test harness transports results.
- **Decision:** Before each row, read the newest execution ID read-only from n8n's SQLite through a throwaway `node` container of the same image (n8n is already stopped for exclusive access). Only when stdout yields no run result, read the executions created after that ID, compacted in the container to the fields `classifyExecution` reads. Accept the result only when exactly one new execution exists, it belongs to `edujobs-workflow-a`, and its Workflow Configuration selected the requested row in runner mode; classify it with the unchanged rules and mark a PASS as verified from the saved execution.
- **Consequences:** No Workflow A node, Sheet read or model call is added; the in-workflow row-isolation verification remains the only PASS evidence. Zero, several or foreign executions, missing saved data, or a failed query keep UNKNOWN and stop the range; a non-zero child exit still fails. Each row adds one short container start for the baseline. Recovery depends on n8n saving execution data and on the local SQLite layout of the pinned image.

- **Context:** Stage 0 normalizes URL representation; Sections 11.x reject LINK_BROKEN only for an objectively broken source. The earlier Project Link fix deliberately left Original Link parsing unchanged, so execution 452 annotated the scheme-less `docs.google.com/document/d/…` as malformed and, once required, rejected it as LINK_BROKEN without fetching.

A bare and an explicit HTTPS form of the same link now compare as equal for duplicates.

### D-020 — Material-gap quotations may span adjacent list items

- **Date:** 2026-09-25
- **Status:** Retired by D-024 (material gaps carry no quotation)
- **Context:** In execution 468 the model's retry quoted adjacent bullet items joined without their `- ` markers; D-016's whitespace-only comparison rejected them and the application became ERROR. Material gaps only withhold MINIMAL/KEEP publication; they never supply publishable facts. `facts_added` evidence, which does support published claims, deliberately forbids removing list markers (enrich-fact-contract task).
- **Decision:** For `material_gaps` only, accept evidence that matches under the D-016 comparison, or that matches after removing line-leading list markers (`-`, `–`, `—`, `•`, `·`, `▪`, `◦`, `●`, a single `*`, or `1.`/`1)` before a space) from both sides and trimming edge punctuation from the quotation. Prompts, schema and the retry error are unchanged.
- **Consequences:** Quotations must still be one uninterrupted run of approved Original Link wording; skipped items, dropped words, paraphrase and noise remain contract violations. A tolerated quotation can at most keep a publication obligation, so the relaxation cannot publish anything. `facts_added` evidence keeps the strict contract.

### D-021 — Editorial sufficiency judged against the submission and the details link

- **Date:** 2026-09-27
- **Status:** Accepted; canonical text amended by the 2026-09-26 Editorial sufficiency amendment (Stage 2, Sections 10.2, 13.0.1, 13.0.2, 13.1, 13.3, 13.10, 14.3, 14.4)
- **Context:** In runs 441–473 the classifier chose ENRICH for 19 of 21 accepted applications, because §13.1 and the prompt treated every Original Link requirement or condition absent from the submission as a gap; with D-016 each ENRICH failure then ended in NEEDS_REVIEW. D-008/D-011 also compared KEEP/MINIMAL with the whole page, so KEEP would have failed rows 3, 4, 6, 14 and 28 even if chosen. The submission form asks applicants only for the essentials, and Workflow B publishes each post with a details link.
- **Decision:** One shared `SUBMISSION_SUFFICIENCY_RULE` feeds the eligibility, source-requirement, ENRICH editor and validator prompts; `material_gaps` records only sufficiency elements. Deterministic completeness in the MINIMAL/ENRICH output check and KEEP validation uses the Short Description and source titles only; approved Original Link content only decides whether an empty candidate lost material. A narrow `meaningIsBareAnnouncement` (a role stem with an optional employer or place and a hiring phrase, but no work description, audience, number, purpose or condition) fails MINIMAL of such a submission and any candidate that is one. The D-011 override forces ENRICH only for such a bare submission when the approved Original Link has an explicit responsibilities section. This supersedes D-008's Original Link completeness reference and D-011's page-facet override, and narrows D-016's records.
- **Consequences:** Sufficient submissions publish through KEEP/MINIMAL without page details; a read-only counterfactual replay of saved 441–473 states shows KEEP passing for every submission except the bare rows 10/19 and row 29 (no employer mention for the link). Details such as Karakuli's learner age are no longer publication obligations. Bare-announcement detection is deliberately high-confidence (for example the existing `час…` condition pattern leaves row 11 to the classifier); ambiguous sufficiency stays in the combined LLM call. Reviewer drafts of sufficient submissions now pass and stay post-ready instead of page dumps. No node, model call, Sheet column or source is added.

### D-022 — Publication post amendment: deterministic boundaries

- **Date:** 2026-10-03
- **Status:** Accepted implementation choices for the 2026-10-03 Publication post amendment (Stage 3, Sections 11.3, 13.0.1, 13.0.2, 13.1, 14.4, 15.1; supersedes D-011's full-context recovery)
- **Context:** The amendment adds a shared soft budget, a contact gate before KEEP, both-link fetching, dead-link rejection for non-required links and a post-shaped reviewer working copy. Several mechanics are left to the implementation.
- **Decision:** (1) `visibleLength` (`workflow-logic/publication-shape.mjs`) counts Unicode code points after replacing each inline link with its text, removing backslash escapes, `**`, `__`, `~~`, backticks and heading markers; single `*`/`_` and list markers count. (2) `findContactChannels` detects email addresses, `@handle` (5–32 characters), `t.me`/`telegram.me`/`wa.me`/`vk.me`/WhatsApp links, `mailto:`/`tg:` and phones that start with `+` or follow the Russian `8-XXX-XXX-XX-XX` shape (hyphen, en/em and non-breaking hyphens allowed), so salaries, years and counts never match; it runs on the unlinked body, so the code-created employer link is exempt. (3) The worker reports a confirmed dead link for HTTP 404/410 and for DNS `EAI_NONAME` only; transient resolver failures stay `FETCH_FAILED`. (4) A reviewer candidate qualifies under §15.1 item 2 only after the semantic validator ran on it; a `OTHER_CONTRACT_VIOLATION` is non-factual only when its text is `project_link_text` or `excluded_material`, otherwise it may hide an unrecorded claim and disqualifies the candidate. (5) The deterministic facet check no longer reports a lost requirements section when the submission states duties, and lines that open with application, contact, details-link or archive-notice wording count as noise in the deterministic meaning measure. (6) The KEEP gates run in Apply Eligibility Decision and route an initial KEEP to MINIMAL; KEEP validation repeats the contact gate for KEEP fallback.
- **Consequences:** No model call, Sheet column or workflow node is added. A contact the detector misses (for example a bare name or "пишите в личку") remains the classifier's and validator's semantic judgment. A link blocked by the remote site stays a technical failure. Over-budget output can still reach READY_FOR_PUBLISH; Workflow B's pre-publication check stops it.

### D-023 — Evidence comparison ignores invisible format characters

- **Date:** 2026-10-06
- **Status:** Accepted implementation choice (refines D-016 and D-020); since D-024 it applies to `facts_added` evidence only
- **Context:** In execution 520 the OSTAZ Project Link page carried a U+200C zero-width non-joiner before «ОSТАZ». The ENRICH editor's quotation was visually exact but lacked the invisible character, so the whitespace-only comparison reported UNSUPPORTED_FACT; the chain fell back to KEEP and published the submission unchanged.
- **Decision:** Before the existing whitespace normalization, both `facts_added` evidence comparison and `material_gaps` evidence comparison remove Unicode format characters (`\p{Cf}`: zero-width space/joiners, word joiner, BOM, bidirectional marks) and the soft hyphen U+00AD from both the quotation and the approved context. Stored context and evidence are unchanged.
- **Consequences:** Any visible difference — letters, digits, punctuation, list markers outside D-020 — still fails. A quotation can now match across an invisible character that the source shows as nothing.

### D-024 — Semantic responsibility amendment: one owner per judgment

- **Date:** 2026-10-07
- **Status:** Accepted implementation choices for the 2026-10-06 Semantic responsibility amendment (Stages 1–3, Sections 6.7, 10.1, 10.2, 11, 14.1, 14.3, 17, 18, 19.4); supersedes D-015 and D-017, retires D-020 and D-016's quotation format.
- **Context:** Runs 486–533 showed that five of six validator FAILs on the publication path contradicted the spec (requirements and quotation wording treated as obligations), that SourceRequirementDecision guessed without seeing the sources and changed a terminal outcome (row 8, execution 504), and that the prompts repeated the whole specification to every role. An offline replay of saved inputs measured the alternatives before any live run. The amendment leaves the mechanics below to the implementation.
- **Decision:** (1) A deterministic `Plan Source Acquisition` node replaces the requirement call, its contract retry and the required-source short circuit; an unsupported social link gets source status `unsupported_social` and is never fetched, and a technical failure keeps `extraction_failed` with the worker error code and no content. (2) The eligibility payload describes each link by URL, status, error code, source type, page title and content; `selector_relation`/`selector_reason` appear only when the large-source selector ran, so the default `RELEVANT` of directly passed text is no longer shown as a judgment. (3) Contract checks: `material_gaps` is a non-repeating subset of EMPLOYER, ROLE and WORK, only for ACCEPT with ENRICH and only when some link content is approved; NO_PROJECT_LINK, NO_VALID_CONTACT, TELEGRAM_BOT_CONTACT and DUPLICATE_APPLICATION are Stage 1 codes and invalid from the classifier; SOCIAL_LINK_ONLY needs a submitted unsupported social link, whose URL may be its evidence. (4) The accepted ENRICH editor receives the gap elements, and every editor receives the submission's visible length, in `workflow_metadata`. (5) The validator receives the editor's sanitized body before link insertion and no `project_link_text`; ValidationResult issues carry type, text and reason only; a non-factual OTHER_CONTRACT_VIOLATION is only `excluded_material`. (6) Prompts are role-specific: one shared sufficiency, post-element and excluded-material core; opening grammar only for editors, with positive examples and no banned-phrase examples; the Section 11 policy in compact form; one-line schema descriptions that no longer repeat the prompts; operator-facing reasons in Russian; one shared contract-retry notice. (7) Optional `VALIDATOR_REASONING_EFFORT` (empty means the provider default) sets `reasoning.effort` on validator requests only. (8) KEEP review reasons are written in Russian. (9) `n8n/eval-replay.mjs` replays saved Sheet rows and worker responses through any generated workflow outside n8n with live model calls only; `n8n/eval-cases.mjs` holds fixed faithful and corrupted validator cases.
- **Consequences:** 128 → 119 nodes and one model call fewer per application. In the offline replay of the final prompts (rows 2–13, five repeats, `gpt-6-luna`, validator effort `high`): READY 40/60, the same outcome in every repeat for every row except row 8 (four NEEDS_REVIEW, one NON_CORE_ADMIN_OPS), ENRICH first pass 30/30, validator FAIL 1/54, no READY text over 900 visible characters; the validator cases pass 54/55 faithful drafts and catch 50/50 corrupted ones (old prompts: 40/55 and 49/50 on `gpt-6-luna`, 45/55 and 47/50 on `gpt-5.6-luna`). A wrong but present selection now links those words without semantic review (accepted cosmetic risk), and an identity mismatch missed by EligibilityDecision is no longer caught by the validator. Offline replay is not live acceptance; the live sandbox run remains the acceptance step.

### D-025 — Intake Trigger locates added rows and calls Vacancy Intake per row

- **Date:** 2026-10-24
- **Status:** Accepted implementation choices for the 2026-10-24 Server installation amendment (Sections 4.1, 22.1).
- **Context:** In n8n 2.35.7 the Google Sheets Trigger `Row Added` event returns the values of the added rows without `row_number`, remembers only how many rows the tab had, and returns every row when run manually. A called workflow runs its published version, and a caller cannot be published before its callee. Workflow A reads its row from `WORKFLOW_A_RUNNER_ROW_NUMBER`/`WORKFLOW_A_TEST_ROW_NUMBER`.
- **Decision:** (1) Vacancy Intake gets a second entrypoint, `When Executed by Another Workflow`, with one number input `row_number`; `Workflow Configuration` uses it whenever the input is present (a missing value becomes 0 and fails row selection) and otherwise falls back to the environment, so the sandbox runner and manual runs are unchanged. (2) Intake Trigger polls every 5 minutes with the service account, reads the tab once with the same value rendering as Workflow A, and locates each added row as the single row without `application_id` whose five raw columns equal the added values (compared as text), claiming each row once; zero or several matches leave the row unlocated. (3) It refuses non-production (manual) executions, so a test click never processes the whole tab. (4) Execute Workflow runs once per located row, waits for each call and continues after a failed call; a final Code node fails the execution and lists unlocated rows and failed calls, or reports the processed row numbers. If nothing was located the execution fails immediately. (5) The same builder writes `workflow-a-intake-trigger.json` next to the Workflow A output (ignored by git); IDs `edujobs-workflow-a` and `edujobs-intake-trigger`; names `EduJobs v2 · Vacancy Intake` and `EduJobs v2 · Intake Trigger`.
- **Consequences:** 119 → 120 Workflow A nodes; the Intake Trigger has five nodes and no worker, LLM or Sheet write. Deleting, inserting or sorting rows, or reimporting the trigger, breaks or resets added-row detection; such rows are processed manually (docs/SERVER_RUNBOOK.md). Two polls can overlap only when one poll's calls outlast five minutes; duplicate detection reads raw columns of earlier rows, so overlap does not change outcomes.
