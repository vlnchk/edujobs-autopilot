## B-D006 — O-003 resolved: atomic claim-tab fence and one Sheets commit

- **Date:** 2026-09-10. **Status:** Accepted for M2 within the documented Sheets limitations.
- **Claim rule:** One hidden `_Workflow B Claim` tab, `A1 = batch_id`, is a disposable coordination fence, not a batch or application store. Creating a new batch requires adding this uniquely named tab with an unused numeric sheet ID in the **same** `spreadsheets.batchUpdate` request as every batch/item append, application association, and control reset. Competing plans attempt to add the same title; an already-existing title/ID rejects the request. Canonical content lives only in Publication Batches and Publication Batch Items.
- **Active definition:** Every valid batch whose status is not `COMPLETED` is unfinished: `CREATED`, `PUBLISHING`, `FAILED`. Any such batch blocks new creation and is reconstructed. Multiple unfinished batches, unknown states, orphan claims/items, missing claim, duplicate identities, invalid source references, inconsistent rendered content, missing items, or false COMPLETED evidence stop deterministically. A completed record must have start/end acknowledgement IDs, timestamps, and SENT items with required metadata; M2 never produces those values.
- **Historical turnover:** If no unfinished batch exists, a fence referencing a verified completed batch can be replaced. Delete only the specific old sheet ID read by this execution, then add a new fence with a higher ID in the atomic commit. A stale contender cannot delete the winner's different ID; its request fails. Application success/claims also consult frozen item persistence, protecting against missing application-side metadata.
- **Failure boundaries:** Preflight and request-size validation occur before writes. All new-batch mutations use one API request, never sequential per-row writes. Google documents all-or-nothing validation and atomic application of the request. Thus this writer cannot commit a half-batch from a rejected request. If the response is lost, the graph re-reads workbook metadata and B persistence, validates the snapshot and exposes the stored batch (including a competing winner). If read-back fails or no committed batch is found, stop and re-run from Manual Trigger. Never clear an active claim, rebuild missing frozen content from Applications, or blindly retry the old commit. Incomplete external/legacy/manual persistence is detected and requires repair from known frozen evidence; absent evidence remains a stopped manual recovery case.
- **Precise limitation:** This is an atomic **write**, not a serializable transaction spanning the earlier reads. Google explicitly permits collaborator changes to alter the resulting sheet; it does not document compare-and-swap cells or general serializable read/write isolation. Unique tab/ID conflicts are the strongest low-complexity guard used here and are simulated locally, but live concurrent behavior remains a manual verification item. Concurrent operator/script row or column insertion, sorting, deletion, header edits, control toggles, or manual fence removal can invalidate read-time row references or consume a newer action. During creation, keep Applications structure and the control stable and give B exclusive ownership of its persistence/fence tabs. Normal post-snapshot content edits cannot change frozen content. If metadata and values reads straddle another commit, consistency checks may stop conservatively; rerun fresh. No stronger cross-client guarantee is claimed.
- **Source:** [Google Sheets spreadsheets.batchUpdate contract](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/batchUpdate). This avoids generic locks, external services, extra databases, or assumptions about n8n execution concurrency settings.

## B-D009 — O-005 resolved: Original Link destination and derived display label

Do not trim, normalize, decode, re-encode, remove tracking parameters, or fetch it. Structurally unusable raw HTTP(S) inputs fail `INVALID_DETAILS_LINK` in whole-batch preflight rather than being repaired. Validation is a small string-based structural check, not DNS/source verification; it requires a nonempty authority and rejects whitespace, literal backslashes/angle brackets, user-info and malformed bracketed-authority syntax. It uses no browser URL global, which is absent from the target n8n Code sandbox.
- **Display label:** Derive on every render from the supplied Original Link: remove its leading HTTP(S) protocol and take the portion before the first literal `?` or `#`. Removing a fragment from the label follows the requested domain-and-path presentation; fragments remain intact in the destination. Preserve path spelling, trailing slash, case and percent escapes. Do not introduce a separate editable or persisted display-text value. The helper's transient `{ href, text }` result is derived data only.
- **Rendering:** The existing Markdown-oriented renderer now emits `[derived label](full destination)` in the details section. Escape Markdown syntax where necessary so literal label characters, parentheses in destinations and entity-looking ampersands cannot change the decoded link. This is presentation escaping, not URL rewriting; frozen `details_link` and helper `href` are always the original string. See the [CommonMark link syntax](https://spec.commonmark.org/0.31.2/#links) and [character-reference rules](https://spec.commonmark.org/0.31.2/#entity-and-numeric-character-references). This does not choose a Telegram API, parse mode, send path or acknowledgement policy; O-006/O-007 remain open.
- **Canonical example:** Original Link/href `https://hh.ru/vacancy/137336583?hhtmFrom=vacancy_search_list`; display `hh.ru/vacancy/137336583`; rendered Markdown `[hh.ru/vacancy/137336583](https://hh.ru/vacancy/137336583?hhtmFrom=vacancy_search_list)`.
- **Freezing and compatibility:** Before snapshot creation, render from the latest Original Link read. Persist the unchanged full URL and the complete frozen rendered message already required by M1/M2; the label is not separately stored. Later renders derive the label from the supplied frozen URL, not mutable Applications. Existing persisted snapshots remain immutable. Reconstruction recognizes the exact current or pre-O-005 assembly format and returns the stored text without rewriting it, including historical presentation-text inputs. New creation can only use O-005 rendering. No Sheet migration, label cache, transport abstraction, or legacy-source fallback in new selection is added.

An unset/empty old `WORKFLOW_B_DETAILS_LINK_COLUMN` needs no replacement; the old value `Original Link` is accepted for existing test installations. Any other nonempty value fails with `O005_ORIGINAL_LINK_ONLY`. New default workflow/config labels are `workflow-b-m2-o005-v1` / `m2-o005-v1`; explicitly provided deployment labels still apply.
- **Verification boundary:** Local domain, Sheets and generated-graph regressions cover the example, exact URL preservation, escaping, dynamic derivation, no fallback, latest edits, frozen persistence and legacy reconstruction. The earlier successful operator test predates this change. Updated live Sheets/Telegram click behavior is not claimed; the O-005 test procedure is recorded in the M2 runbook. ## B-D014 — M4 manual whole-batch publication restart

- **Date:** 2026-09-19. **Status:** Implemented; verification evidence is recorded in WORKFLOW_B_IMPLEMENTATION_STATUS.md.
- **Explicit product decision:** **Publication recovery is manual whole-batch restart. Preflight prevents avoidable failures; runtime Telegram failures are handled by operator cleanup and full retry. No publisher ownership/takeover or partial resume is implemented.**
- **Preflight/reset:** Reconstruct the entire frozen batch, encode every final payload, validate source/association targets, then verify the configured Telegram channel, bot and posting permission. Only after all checks pass, reset delivery metadata for every FAILED batch/item/Application row in one atomic Sheets request and commit PUBLISHING. Start the in-memory sequence at zero. CREATED uses the same preflight without rewriting frozen data. Identity, content, order, timestamps of creation and versions remain unchanged. Prior delivery evidence may disagree after a failed attempt; source identities/associations must still agree, and every delivery field is cleared on retry.
- **Failures:** Every Telegram failure, including structured 429 with delay and native string/network uncertainty, records FAILED plus concise cleanup/full-restart instructions and stops sending. Keep all durable delivery evidence until retry. No automatic Telegram retries, waits, deletion or reconciliation.
- **Necessary persistence choice:** On an unconfirmed acknowledgement write, read only the batch table once before recording failure. If END already committed COMPLETED, leave it immutable and report PUBLICATION_ALREADY_COMPLETED. Otherwise write only FAILED/diagnostics, preserving any item/Application acknowledgements that committed. This is a terminal failure path with no send continuation, read loop, status polling or Telegram reconciliation. If this read or the stop write fails, leave persistence untouched and follow the manual stuck-batch procedure. The initial PUBLISHING/reset commit must be confirmed before any send; its lost response also stops.
- **Operating constraint:** PUBLISHING at startup returns BATCH_ALREADY_PUBLISHING. A status read/write is not atomic compare-and-swap against simultaneous startups; the operator runs one publication at a time. No replacement lock/lease is added. The M2 _Workflow B Claim still protects atomic batch creation and prevents preparing around a FAILED batch.
- **Manual crash recovery:** Confirm in the n8n UI that no publication execution runs, clean all Telegram messages from the attempt, then manually set a stuck PUBLISHING batch to FAILED and rerun publish from Manual Trigger. No confirmation cell, recovery sheet or n8n execution API is involved.
- **Obsolete resources:** `_Workflow B Publisher` is ignored even if malformed, including during setup. It may be manually removed; no migration is implemented. Workflow B requires only the existing Google and Telegram credentials. No n8n API credential or publication coordination identifier remains in runtime code.
- **Boundary:** M0–M3 selection, O-005 Original Link behavior, O-006 HTML transport, frozen snapshot layout, creation claim and completed history are preserved. M5/M6 are not implemented by this task.
